# forji-flow — build notes

## Layout

- `Sources/ScenarioKit/` — the Swift package (product `ScenarioKit`, iOS 16+;
  builds for macOS too so host tooling can compile it). `ScenarioPlan` parses
  steps.json (raw dict preserved on `Step.raw` for app verbs), `ScenarioPlayer`
  is the engine (verb registry + hooks), `Capture` bakes orientation into
  pixels and writes `shots/<scenario>-<label>.png` (+ `main.png` for the poster).
  It imports XCTest — link it into UI-test bundles only.
- `js/` — the browser player on the playwright **library** API (no test-runner
  framework): `player.mjs` (core verbs, selector resolution, failure guards,
  region shots via `of:`, multi-user contexts via `actor:`) + `run.mjs` (the
  CLI). Playwright resolves from the consuming project via `NODE_PATH` or the
  suite's node_modules. The suite's `app.mjs` supplies launch/auth/backend
  setup, an id→locator map, `app:` verbs, and the pre-shot freeze.
- `lint/` — `lint-steps.mjs` (zero-dep schema lint) + `self-test.mjs` +
  fixtures (`good/` must pass, `bad/` plants one of every violation).

## Player hooks (native)

`configureLaunch` (sugar → env/args, pre-launch), `afterLaunch` (orientation
pinning), `afterType` (keyboard dismissal), `beforeShot` (freeze volatile UI),
`resolveElement` (selector override), `captureSource = .screen` (landscape-
locked windows mis-crop `app.screenshot()`).

## Delivery contract (native)

`xcodebuild test … -only-testing <Bundle>/<Case>/testScenario` with
`TEST_RUNNER_APP_SCENARIO`, `TEST_RUNNER_APP_STEPS_JSON` (file contents),
`TEST_RUNNER_UITEST_SHOTS_DIR` (absolute path to the suite's `shots/`).
xcodebuild strips the `TEST_RUNNER_` prefix into the test process. No env →
`XCTSkip` → compile-only gate.

## Verify

```sh
node lint/self-test.mjs
xcodebuild -scheme ScenarioKit -destination 'generic/platform=iOS Simulator' build
```
