# forji-flow — the shared declarative UI-flow tool

The reusable engine behind the `std/flow` contract
(https://forji.ai/std/flow/). Projects declare UI flows as `*.steps.json`
data files; the players here interpret them against the really-running app and
write screenshots into the suite's `shots/` folder (`main.png` = the poster the
node card shows).

## Contract

- **One vocabulary.** `STEPS.md` is the single source of truth: core verbs,
  selectors, shot labels, the `poster` designation, the `app:` namespace for
  suite-registered moves. Every player implements exactly this vocabulary; a
  scenario reads the same on every platform.
- **Core is fixed; apps extend, never fork.** A suite registers `app:` verbs
  and launch sugar with its player. A missing *generic* capability is a change
  to this repo — never a project-local copy of the engine.
- **One player per platform.** Native drives the app through the system UI
  automation; web drives a real browser. Both deliver scenarios at run time
  (no per-scenario compilation) and stay silent no-ops when no scenario is
  delivered, so plain build gates keep passing.
- **The lint is the offline gate.** `lint/lint-steps.mjs` validates any suite's
  scenarios with no device, browser, or dependencies — suites expose it as
  their `test` process.
- `verify`: the lint self-test proves the gate itself (good fixture passes,
  every planted violation in the bad fixture is reported).

## Consumers

Suites conform by inheriting https://forji.ai/std/flow/ in their `.spec.md`;
this repo is consumed by local path (native: Swift package; web: direct
`node js/run.mjs`). See `README.md`.
